# سوق إضافات: kmk-marketplace

إضافة واحدة تُدير بناء أنظمة إدارية عربية RTL بأمر واحد، موجّهة لمستخدمين لا يعرفون البرمجة: موقع (React) + خدمات (Laravel) + تطبيق جوال اختياري (Flutter).

## التثبيت

```
/plugin marketplace add KMK-2025/kmk-plugin
/plugin install kmk-plugin@kmk-marketplace
```

## الاستخدام

```
/start متجري
```

يفحص البيئة، يصلح ما ينقص، ينشئ المشروع كاملًا، ويثبّت داخله ثمانية أوامر:

`/idea` · `/apply-design` · `/build-web` · `/test` · `/share-link` · `/deploy` · `/fix` · `/go-back`

## تطبيق الجوال (اختياري)

```
/add-mobile
```

يجهّز بيئة Flutter على الجهاز إن لزم، ينشئ `mobile/` بنفس بنية الموقع، ويضيف للخدمات فحص الإصدار وتسجيل الأجهزة. بعده:

`/build-mobile` قسم على الجوال · `/test mobile` تجربة على الهاتف الموصول · `/share-link mobile` ملف يثبّته العميل · `/deploy mobile` إصدار جديد

Android يُبنى محليًا على أي نظام. iOS يحتاج Mac، فيُبنى في GitHub Actions.

## نسخ الـ API محميّة آليًا

تطبيق قديم في يد عميل لا يتحدّث فورًا، فتغيير شكل ردّ خدمة يكسره. لذلك:

- **الكشف آلي:** كل اختبار نقطة يحفظ شكل ردّها (`ApiShape`). حذف حقل أو تغيير نوعه لاحقًا يُفشل الاختبار؛ إضافة حقل مسموحة.
- **الرفع آلي:** عند الكسر يشغّل الوكيل `bump-api-version.sh` دون سؤال صاحب المشروع: ينشئ `v(N+1)` تشير نقاطها إلى نفس كود النسخة السابقة، يوجّه الإصدار القادم من التطبيق إليها، ويسجّل السبب في العقد.
- **صمام الأمان:** التطبيق يرسل رقم إصداره مع كل طلب، والخادم يرفض ما دون «أقل إصدار مدعوم» فيعرض التطبيق شاشة «حدّث التطبيق».

## البنية

```
.claude-plugin/marketplace.json     ← فهرس السوق
plugins/kmk-plugin/
├── .claude-plugin/plugin.json      ← تعريف الإضافة
├── skills/{start,add-mobile}/      ← أمرا الإضافة: إنشاء مشروع، وإضافة تطبيق جوال
├── hooks/hooks.json                ← ربط حاجز الأمان
├── scripts/
│   ├── doctor.sh · doctor-mobile.sh  ← فحص البيئة (لا يعدّلان شيئًا)
│   ├── setup-project.sh            ← إنشاء المشروع — حتمي لا توليدي
│   ├── setup-mobile.sh             ← تجهيز Flutter و Android على الجهاز
│   ├── add-mobile.sh               ← إضافة mobile/ وخدماته لمشروع قائم
│   ├── guard.sh                    ← منع الأوامر المدمّرة
│   └── autosave.sh                 ← حفظ تلقائي بعد كل مهمة
├── stubs/backend-core/             ← حارس توافق الـ API لكل مشروع
├── mobile/                         ← طبقة الجوال: التطبيق، موديول الخدمات، الأمر والوكيل
└── templates/                      ← يُنسخ إلى كل مشروع جديد
    ├── CLAUDE.md
    ├── .claude/{skills,agents,scripts,hooks,launch.json,settings.json}
    ├── docs/
    └── .github/workflows/
```

## المبدأ المعماري

**الإضافة تشحن السكربت، والسكيل يشغّله.**

الإنشاء حتمي (سكربت واحد بترتيب ثابت)، والتشخيص والتعامل مع الأعطال محادثة. هذا يمنع اختلاف الناتج بين متدرب وآخر، ويجعل الفشل يقع في نقطة واحدة معروفة بدل مشروع نصف مبني.

**الأوامر الثمانية تُنسخ داخل المشروع ولا تبقى في الإضافة.** فائدتان: المشروع يعمل على أي جهاز بلا الإضافة، والأوامر تُكتب بأسمائها المجرّدة `/build-web` بدل صيغة مركّبة.

## التحديث

عدّل هنا وادفع إلى GitHub، والمستخدمون يحدّثون بـ `/plugin marketplace update`.

⚠️ المشاريع المُنشأة سابقًا **لا تتحدث تلقائيًا** — نسخها من `templates/` مجمّدة لحظة الإنشاء. لتحديث مشروع قائم، أعد نسخ `templates/.claude/skills/` فوقه.
