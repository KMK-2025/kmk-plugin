# دليل المدرب — كل ما هو مطلوب منك، خطوة بخطوة

> **دورك في جملة واحدة:** أنت تبني المصنع مرة واحدة، والمتدرب يشغّل ستة أزرار.
> كل تعقيد يبقى عندك = وقت مكسوب في المحاضرة. كل تعقيد يتسرّب إليه = ساعة ضائعة.

---

> ⚠️ **اقرأ `بيئة-شبيهة-بـ-Lovable.md` قبل هذا الملف.** المتدرب سيعمل في تبويب Code في تطبيق سطح المكتب — محادثة يسار ومعاينة حية يمين، بلا طرفية. خطوات الإعداد أدناه تفترض ذلك.

# 🔹 المرحلة أ — قبل التدريب بأسبوع (عملك أنت وحدك)

**الوقت المطلوب: يوم إلى يومين.**

## أ-1 · جهّز المشروع

ثبّت الإضافة مرة واحدة على جهاز المتدرب:

```
/plugin marketplace add KMK-2025/kmk-plugin
/plugin install kmk-plugin@kmk-marketplace
```

ثم يكفي أمر واحد داخل تبويب Code:

```
/ابدأ نظام-العيادة
```

الأمر يفحص البيئة، يرشد لما ينقص، ينشئ المشروع كاملًا، ويثبّت الأوامر الثمانية داخله.

## أ-2 · اختبر الأوامر العربية — ⚠️ هذه أول نقطة فشل محتملة

```bash
cd نظام-العيادة
claude
```
اكتب `/` وانظر: هل تظهر `فكرة` و `ابن` و `انشر`؟ ثم اكتب `/فكرة` واضغط Enter.

| النتيجة | ما تفعله |
|---|---|
| ✅ تعمل | ممتاز، أكمل |
| ❌ الطرفية لا تقبل العربية، أو المؤشر يقفز | شغّل `bash تبديل-للاتينية.sh` وستصبح: `/idea` `/design` `/build` `/test` `/deploy` `/fix` `/undo` — والبطاقة فيها نسخة بديلة جاهزة |

> افعل هذا الاختبار على **جهاز المتدرب نفسه** لا على جهازك. الطرفيات تختلف.

## أ-3 · اضبط قاعدة البيانات

```bash
cd backend
# عدّل .env: DB_DATABASE, DB_USERNAME, DB_PASSWORD
php artisan migrate
```
أنشئ مستخدمًا للتجربة: `admin@test.com` / `password` — واحفظ البيانات، ستكتبها له في الجلسة.

## أ-4 · اربط GitHub والسيرفر

```bash
git remote add origin git@github.com:<حسابك>/نظام-العيادة.git
git branch -M main && git push -u origin main
git checkout -b staging && git push -u origin staging
```

في GitHub → Settings → Secrets and variables → Actions، أضف:
`SSH_HOST` · `SSH_USER` · `SSH_KEY` · `DB_USER` · `DB_PASS` · `DB_NAME`

على السيرفر جهّز المسارات: `/var/www/app` · `/var/www/api` · `/var/www/staging-app` · `/var/www/staging-api`، مع Nginx وشهادة SSL على النطاقات الفرعية.

## أ-5 · جرّب دورة كاملة بنفسك — ⚠️ لا تتخطَّ هذه

نفّذ بنفسك، قبل المتدرب بأسبوع:
`/فكرة` → `/ابن قسم تجريبي` → `/جرب` → `/انشر تجربة` → `/تراجع`

**كل عثرة تجدها هنا هي عثرة لن تحدث أمامه.** أصلحها بتعديل السكيل المعني، لا بتذكّرها في رأسك.

## أ-6 · قرار الحفظ التلقائي

الحفظ التلقائي مُفعَّل افتراضيًا: بعد كل مهمة تُحفظ نقطة تلقائيًا، فلا يحتاج تعلّم Git إطلاقًا — يكفيه `/تراجع`.

- **أبقِه** إن كان سيعمل وحده أو مع فريق صغير غير تقني.
- **عطّله** (احذف قسم `"Stop"` من `.claude/settings.json`) إن كان سينضم لفريق مبرمجين لاحقًا — لأن تاريخ الـ commits سيصبح فوضويًا، وستحتاج تعليمه Git على أي حال.

## ✅ قائمة تحقق قبل المغادرة

- [ ] السكربت أنشأ المشروع بلا أخطاء
- [ ] الأوامر تظهر وتعمل **على جهاز المتدرب**
- [ ] قاعدة البيانات تعمل ومستخدم التجربة موجود
- [ ] GitHub مربوط والأسرار مضافة
- [ ] النشر على staging نجح مرة واحدة على الأقل
- [ ] جرّبت الدورة الخمسة كاملة بنفسك
- [ ] البطاقة مطبوعة على ورق

# 🔹 المرحلة ب — قبل المحاضرة بيوم (على جهاز المتدرب)

**الوقت: ساعة.**

ثبّت وتأكد أن كل واحد يعمل:

| الأداة | التحقق |
|---|---|
| Node.js LTS | `node -v` |
| Git | `git --version` |
| PHP 8.2+ · Composer | `php -v` · `composer -V` |
| MySQL (أو Docker) | يتصل فعلًا |
| Claude Code | `claude --version` |
| حساب Claude | مسجَّل دخول ويعمل |

ثم انسخ مجلد المشروع إلى جهازه، شغّل `claude`، وتأكد أن الأوامر تظهر.

> ⚠️ **قاعدة حاسمة: لا تُنصّب شيئًا أمامه في المحاضرة.** التنصيب يعطب دائمًا، وأول عشرين دقيقة من التدريب هي أثمن ما فيه. اذبح هذا التنين في غيابه.

# 🔹 المرحلة ج — الجلسة الأولى (90 دقيقة)

## 🕐 الدقائق 0–15 · نتيجة على الشاشة قبل أي شرح

**لا تشرح شيئًا.** لا تعريف بنفسك، لا مقدمة عن الذكاء الاصطناعي، لا شرائح.

افتح جهازه واكتب أنت:

```
claude
/فكرة
```

ثم قل: **"جاوب على أسئلته بلغتك العادية."**

اتركه يجيب على 4–5 أسئلة، ثم اكتب:
```
/ابن <أول قسم ذكره>
```
ثم `/جرب` — وافتح المتصفح على شاشة تعمل ببياناته هو.

قل جملة واحدة فقط:
> **"هذا نظامك، وأنت اللي عملته. كل اللي جاي شرح لهذول الأوامر."**

**لماذا هذا الترتيب:** من يرى نتيجة في أول ربع ساعة يتعلّم بقية الوقت وهو مندفع. من يسمع نظرية عشرين دقيقة يفقد الاهتمام قبل أن يبدأ.

**علامة نجاح:** يقول "إيش؟ هيك بس؟" أو يبتسم.

---

## 🕐 الدقائق 15–30 · الأشياء الأربعة — كل ما يحتاج فهمه

اشرح أربعة أشياء فقط. **لا تزد شيئًا مهما بدا مهمًا.**

### 1️⃣ الشكل غير المعلومات
> "النظام عنده وجهين: اللي أنت تشوفه بعينك — الشاشات والأزرار. واللي مخبّى — مكان تخزين المعلومات. لما أضفت مريض قبل شوي، ظهر بالشاشة **وانحفظ** بالمخزن. لو سكّرت المتصفح وفتحته، بيضل موجود."

**لا تقل frontend ولا backend ولا database.** ولا مرة.

### 2️⃣ كل شي إله زر تراجع
اكتب أمامه شيئًا واضحًا (غيّر لون النظام مثلًا)، ثم:
```
/تراجع
```
دعه يرى الشيء يرجع.
> "ما في شي بتعمله ما بينرجع. جرّب براحتك — أسوأ شي راح يصير إنك تكتب `/تراجع`."

**هذه أهم لحظة في المحاضرة كلها.** الخوف من الكسر هو ما يشلّ غير المبرمجين. اقتله هنا.

### 3️⃣ جهازك ≠ الإنترنت
> "كل اللي عملناه لسه على جهازك بس. ولا حدا بالعالم بيشوفه. لما تكتب `/انشر`، وقتها بس بيطلع للناس."

### 4️⃣ كيف تطلب
اكتب على السبورة:
```
شو بدي   +   على أي نمط   +   كيف بعرف إنه ظبط
```
مثال حي:
> "بدي شاشة الفواتير، نفس شكل شاشة المرضى بالضبط، وبعرف إنها ظبطت لما أقدر أضيف فاتورة وأشوفها بالقائمة."

## 🕐 الدقائق 30–85 · هو يشتغل وأنت صامت

**هذا أصعب جزء عليك أنت، لا عليه.**

أعطه البطاقة وقل: **"كمّل نظامك. أنا هون بس إذا وقفت."**

### قواعد صمتك

| الموقف | ما تفعله |
|---|---|
| يكتب أمرًا خطأ | **لا تصحّحه.** Claude سيسأله ويصحّح نفسه. تدخّلك يعلّمه أن يعتمد عليك. |
| يظهر خطأ أحمر | **لا تقرأه.** قل: "اكتب `/اصلح` واحكيله شو صار." |
| ينسى أمرًا | أشِر إلى البطاقة بإصبعك ولا تنطق. |
| يسأل "ليش هيك؟" | جاوب بجملة واحدة قصيرة وارجع للصمت. |
| صامت وينظر إليك | انتظر عشرين ثانية كاملة قبل أن تتكلم. أكثر مما تظن، سيكمل وحده. |
| **يعلق فعلًا 5 دقائق** | تدخّل، لكن **بيديه هو على الكيبورد** — أمْلِ عليه، لا تكتب أنت. |

### سجّل لنفسك ولا تعلّق بصوت
اكتب في ورقة كل نقطة تعثّر. **كل واحدة منها هي سكيل ناقص أو صياغة سيئة في سكيل موجود** — ستصلحها بعد المحاضرة، لا فيها.

---

## 🕐 الدقائق 85–90 · الإغلاق

- اعرض عليه ما بناه اليوم بنفسه.
- الواجب: **"ضيف قسم واحد جديد قبل الجلسة الجاية."**
- الجلسة القادمة: "بنطلّع نظامك على الإنترنت."

# 🔹 المرحلة د — الجلسة الثانية (90 دقيقة)

## 🕐 0–10 · مراجعة الواجب
اسأل: "وين وقفت؟" — مكان تعثّره يخبرك بالضبط أي سكيل يحتاج تحسينًا.

## 🕐 10–30 · التصميم
- افتح Claude Design واصنع شاشة أمامه.
- علّمه **بروتوكول التسليم فقط**: لقطة شاشة → مجلد `docs/design` → `/صمم`.
- لا تشرح CSS ولا متغيرات ولا شيئًا عن نظام التصميم.

## 🕐 30–50 · النشر على التجربة
```
/انشر تجربة
```
دعه يرى الفحوصات تجري ثم الرابط يعمل. افتحه من **جواله** — هذه اللحظة تترك أثرًا أكبر من كل الشرح.

## 🕐 50–65 · النشر الحقيقي
```
/انشر حقيقي
```
سيرفض ويطلب كلمة **انشر**. اشرح لماذا هذه الخطوة الإضافية موجودة، ثم انشر.

## 🕐 65–80 · اكسر شيئًا عمدًا — ⚠️ الجزء الأهم في الجلسة

أمامه، احذف حقلًا مطلوبًا أو اقطع اتصال قاعدة البيانات. دع النظام يتعطل فعلًا.

اتركه في التعطل **ثلاثين ثانية كاملة**. ثم قل: "اكتب `/اصلح`."

> **لماذا:** أول عطل حقيقي بعد التدريب سيكون وحده في مكتبه. إن كان قد رأى عطلًا وشُفي أمامك، سيكتب `/اصلح` بثقة. إن لم يرَ، سيتصل بك — وسيتصل كل مرة.

## 🕐 80–90 · خطة ما بعد التدريب
- نسخة احتياطية يومية (اشرح أنها تلقائية — لا تعلّمه إياها)
- متى يتصل بك: **فقط** إن كتب `/اصلح` مرتين ولم تُحل
- الواجب: قسم جديد كامل من الفكرة حتى النشر، وحده

# 🔹 المرحلة هـ — الأسبوع الأول بعده

| اليوم | ما تفعله |
|---|---|
| اليوم 1 | رسالة قصيرة: "كيف ماشي؟" — لا شيء أكثر |
| اليوم 3 | افتح مستودعه وانظر نقاط الحفظ. هل يعمل فعلًا؟ |
| اليوم 7 | **جلسة مراجعة 30 دقيقة** — أهم جلسة في البرنامج كله |

## في جلسة اليوم السابع

اسأله سؤالين فقط:
1. "شو أكثر شي وقفك؟"
2. "شو الشي اللي حسّيت إنك محتاج تسألني عنه؟"

كل إجابة تحوّلها إلى **تعديل في المصنع**، لا إلى شرح إضافي له:

| ما قاله | ما تفعله أنت |
|---|---|
| "ما عرفت كيف أعمل تقرير" | أضِف سكيل `/تقرير` |
| "الأوامر ما بتطلع" | أصلح مشكلة الطرفية أو حوّل للأسماء اللاتينية |
| "ما فهمت شو بدو مني" | عدّل صياغة السكيل ليسأل أوضح |
| "خفت أنشر" | أضِف خطوة تأكيد إضافية أو معاينة قبل النشر |

> **القاعدة الذهبية للبرنامج كله:** كل سؤال يصلك مرتين = نقص في المصنع، لا نقص في المتدرب. أصلح المصنع.

**لا تتكلم ولا كلمة.**

| النتيجة | المعنى | ما تفعله |
|---|---|---|
| أنجزه وحده | ✅ التدريب نجح | سلّمه المشروع |
| توقف مرة أو مرتين وأكمل | 🟡 جيد | حسّن السكيلز التي تعثّر فيها |
| توقف كثيرًا | 🔴 المشكلة في المصنع | راجع السكيلز، لا تعِد الشرح |

# 🔹 توسيع المصنع لاحقًا

عند الحاجة لأمر جديد، أنشئ مجلدًا في `.claude/skills/<الاسم>/SKILL.md` على نفس نمط الموجود، والتزم بثلاث قواعد:

1. **يسأل سؤالًا واحدًا في كل مرة**
2. **يعرض الخطة بلغة بسيطة وينتظر الموافقة**
3. **ينتهي باقتراح الأمر التالي**

⚠️ **لا تتجاوز عشرة أوامر إجمالًا.** الكثرة تربك Claude في الاختيار وتربك المتدرب في التذكّر. إن احتجت الحادي عشر، ادمج اثنين موجودين.

غلّف `.claude/` كاملًا في Plugin على GitHub، فيصبح تجهيز أي مشروع جديد أمرًا واحدًا — وهذا هو الشيء الثابت الذي يخدم كل تدريباتك القادمة.
