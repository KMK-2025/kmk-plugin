# إنشاء مشروع جديد: $ARGUMENTS

أنت تخاطب شخصًا **لا يعرف البرمجة**. لا تعرض عليه مخرجات أوامر خام، ولا مصطلحات تقنية. اعرض تقدّمًا بلغة بسيطة، وتوقّف عند كل عقبة واشرحها بجملتين.

---

## قاعدة الاستئناف

السكربت يسجّل كل مرحلة يُتمّها في `.setup-state` داخل مجلد المشروع، **ويكمل تلقائيًا من حيث توقّف** عند إعادة تشغيله بنفس الأمر.

فإن فشل شيء: أصلح السبب ثم **أعد تشغيل نفس الأمر**. لا تحذف المجلد ولا تبدأ من جديد.

---

## المرحلة 1 — الفحص

```bash
bash "${CLAUDE_PLUGIN_ROOT}/scripts/doctor.sh"
```

اقرأ التقرير وصنّف النتيجة:

### أ) كل شيء جاهز
أخبره بجملة واحدة وانتقل للمرحلة 2.

### ب) `mysql` مفقود لكن XAMPP مثبّت
هذه أكثر حالة شيوعًا على Windows. **لا تطلب منه تثبيت أي شيء.**

1. إن كان `MYSQL_RUNNING=لا` قل:
   > "محتاج منك شغلة وحدة: افتح **XAMPP Control Panel** واضغط **Start** جنب **MySQL**. قل لي لما يصير أخضر."
   وانتظره.
2. ثم أضف المسار للجلسة الحالية بنفسك:
   ```bash
   export PATH="$PATH:<XAMPP_PATH>/mysql/bin"
   ```
3. ولتثبيته دائمًا، اسأله أولًا ثم نفّذ:
   ```bash
   echo 'export PATH="$PATH:<XAMPP_PATH>/mysql/bin"' >> ~/.bashrc
   ```
4. أعد تشغيل الفحص للتأكد.

### ج) منفذ مشغول
إن كان `PORT_8000=مشغول` فغالبًا Apache من XAMPP. أخبره:
> "المنفذ اللي بدنا نشغّل عليه الخدمات مشغول ببرنامج ثاني. تحب توقّف **Apache** من XAMPP، ولا نشغّل على منفذ ثاني؟"

وإن كان `PORT_3306=مشغول` بينما MySQL متوقف في XAMPP، فهناك MySQL آخر يعمل — اسأله أيّهما يريد استخدامه.

### د) إضافة PHP مفقودة
حدّد السطر في `PHP_INI` وأخبره:
> "في إعداد صغير ناقص بـ PHP. تحب أفعّله؟ بغيّر سطر واحد بس."

بعد موافقته: أزل `;` من أول السطر `;extension=<الاسم>`، ثم **أعد تشغيل MySQL/Apache من XAMPP** وأعد الفحص.

### هـ) أداة أساسية مفقودة (node أو php أو git أو composer)
**لا تثبّتها من تلقاء نفسك.** اعرض عليه الأمر واطلب إذنًا صريحًا:

| الأداة | Windows | macOS |
|---|---|---|
| Node.js | `winget install OpenJS.NodeJS.LTS` | `brew install node` |
| Git | `winget install Git.Git` | مثبّت افتراضيًا |
| PHP + MySQL | `winget install ApacheFriends.Xampp.8.2` | `brew install php mysql` |
| Composer | `winget install Composer.Composer` | `brew install composer` |

⚠️ **بعد أي تثبيت، المسارات لا تظهر في الجلسة الحالية.** قل له حرفيًا:
> "تم التثبيت ✅ بس لازم تسكّر التطبيق وتفتحه من جديد عشان يشوف الأدوات الجديدة. بعدين اكتب `/ابدأ $ARGUMENTS` مرة ثانية وبنكمل من وين وقفنا."

وأنهِ دورك هنا. **لا تحاول الالتفاف على هذا** — لن يعمل.

### و) إصدار قديم
`NODE_MAJOR` أقل من 20 أو `PHP_OK=لا`: أخبره أن الأداة قديمة واعرض أمر التحديث، ولا تكمل.

### ز) الصدفة خاطئة على Windows
إن كان `SHELL_OK` سلبيًا، أخبره أن الجلسة يجب أن تعمل عبر Git Bash، وتوقّف.

## المرحلة 2 — إنشاء المشروع

اسأله عن اسم المشروع إن لم يذكره. اقترح اسمًا إنجليزيًا بحروف صغيرة وشُرَط، بلا مسافات ولا حروف عربية — **مسارات فيها مسافات تكسر الأدوات على Windows**، فاشرح ذلك بجملة واحدة إن اقترح اسمًا فيه مسافة.

```bash
bash "${CLAUDE_PLUGIN_ROOT}/scripts/setup-project.sh" <الاسم>
```

**إن كانت لقاعدة البيانات كلمة سر** (يظهر ذلك من `DB_CONNECT` في الفحص، أو يفشل السكربت برسالة صريحة)، اسأله عنها ومرّرها:

```bash
bash "${CLAUDE_PLUGIN_ROOT}/scripts/setup-project.sh" <الاسم> root <كلمة-السر>
```

يأخذ ٥–٨ دقائق. أخبره بذلك قبل أن تبدأ حتى لا يظن أن شيئًا تعطّل.

السكربت يتولّى كل شيء بنفسه: الواجهة والخدمات وقاعدتَي البيانات وملفات الإعداد
والجداول والأدوار والمستخدم الأول وفحوصات الجودة وأول نقطة حفظ.
**لا تنسخ ملفات يدويًا ولا تعدّل `.env` — هو يفعل ذلك.**

**إن فشل:** لا ترقّع. اقرأ رسالة الخطأ التي يطبعها (يعرض آخر ٣٠ سطرًا من السجل)، اشرح السبب بجملتين، أصلحه، ثم **أعد تشغيل نفس الأمر** — سيُكمل من حيث توقّف.

## المرحلة 3 — التحقق بعينك

شغّل الواجهة والخدمات من إعداد المعاينة، وافتح الواجهة في لوحة المعاينة، ثم:

1. تأكد أن صفحة الدخول تفتح.
2. سجّل دخولًا بـ `admin@test.com` / `password`.
3. تأكد أنك وصلت إلى الصفحة الرئيسية بعد الدخول.

**لا تعلن النجاح قبل أن ترى ذلك بنفسك.**

⚠️ **الشكل سيكون بسيطًا جدًا وبلا تنسيق — وهذا صحيح ومقصود.** التصميم يأتي في `/صمم`.
إن بدا النظام مصمَّمًا من الآن فهذه مشكلة لا ميزة.
