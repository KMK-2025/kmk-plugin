# بناء موديول كامل: $ARGUMENTS

## اقرأ أولًا
`docs/spec.md` · `docs/api-contract.md` · `docs/design-system.md` · `CLAUDE.md` (خصوصًا **الأساس التقني** و **نقاط الإضافة الثلاث** والنسخ والأمان والتسمية).

ثم اقرأ **الموديولين المرجعيين** — هما أدقّ من أي وصف:
- `backend/app/Modules/Auth/`
- `frontend/src/features/auth/`

وافحص `app/Modules/` و `src/features/` و `src/shared/` لتعرف ما هو موجود للاستخدام.

> ⚠️ الأساس التقني موجود ويعمل: عميل الخدمات، غلاف الردود، المصادقة، الصلاحيات،
> بنية المسارات، مكونات الحالات، خطّافات القوائم. **لا تعِد بناء أيٍّ منها.**

## المرحلة 1 — الخطة (إلزامية قبل أي كود)

اعرض عليه خطة **بلغة غير تقنية** بهذا الشكل:

> "راح أبني قسم «الفواتير». هذا اللي فهمته:
>
> **المعلومات اللي راح نحفظها:** رقم الفاتورة، اسم العميل، التاريخ، المبلغ، الحالة (مدفوعة/معلّقة)
> **الشاشات:** قائمة الفواتير · شاشة إضافة وتعديل · شاشة التفاصيل
> **من يقدر يستخدمه:** المدير كل شيء، المحاسب يضيف ويعدّل ولا يحذف
> **مرتبط بـ:** قسم العملاء
>
> صح؟ في شي ناقص أو زيادة؟"

**لا تكتب سطرًا واحدًا من الكود قبل أن يقول نعم.**

إن كان القسم غير موجود في `docs/spec.md`، اسأله عن التفاصيل الناقصة سؤالًا سؤالًا، ثم أضِف القسم إلى `spec.md`.

حدّد اسم الموديول الإنجليزي (StudlyCase جمع للخدمات، kebab-case جمع للواجهة) — نفس الاسم في الجهتين.

**ثم اكتب العقد قبل البناء:** أضِف نقاط الموديول وحقولها إلى `docs/api-contract.md`
أولًا. الجهتان تبنيان على عقد متّفق عليه، لا تلاحق الواجهة ما تقرّره الخدمات.

## المرحلة 2 — البيانات والخدمات (Laravel + MySQL)

فوّض هذه المرحلة إلى الوكيل `laravel-api-builder`.

المطلوب منه — كله داخل `app/Modules/<Module>/` وتحت نسخة `V1`:
1. Migration بترميز `utf8mb4_unicode_ci` وفهارس على أعمدة البحث والفرز
2. `Models/<Entity>.php` + العلاقات + `$fillable` + `$hidden` للحساس + `LogsActivity`
3. `Http/Requests/V1/` للإنشاء والتعديل برسائل خطأ **عربية**
4. `Services/<Entity>Service.php` يحمل المنطق، و Controller نحيف: `index` (بحث/فرز/ترقيم عبر `InteractsWithListQuery`) · `show` · `store` · `update` · `destroy`
5. `Http/Resources/V1/` — والردود عبر `ApiResponse::success()` و `ApiResponse::paginated()` حصرًا
6. `routes/api/v1/<module>.php` محمي بـ `auth:sanctum` + `permission:` (يُحمَّل تلقائيًا)
7. **إضافة الصلاحيات إلى `RolePermissionSeeder::$permissions`** ثم `php artisan db:seed --class=RolePermissionSeeder`
8. Seeder ببيانات عربية واقعية (10 سجلات على الأقل ليظهر الترقيم)
9. اختبارات Pest في `tests/Feature/<Module>/V1/`: نجاح · فشل تحقق · 401 · 403 — باستخدام `actingAsAdmin()` و `actingAsStaff()`
10. البوابة: `./vendor/bin/pint && ./vendor/bin/phpstan analyse && php artisan test`

## المرحلة 3 — الشاشات (React)

فوّض هذه المرحلة إلى الوكيل `frontend-builder`.

المطلوب منه — كله داخل `src/features/<feature>/`:
1. `types/<entity>.ts` مطابق حرفيًا لاستجابة الـ API في العقد
2. `services/<feature>.service.ts` عبر `http` من `shared/api` — كل الاستدعاءات هنا حصرًا، بلا `/v1/` يدوية
3. `pages/`:
   - **صفحة القائمة**: `useListParams()` + `useListQuery<T>()` من `shared/hooks` للحالة
     (صفحة، بحث مؤجّل، فرز)، ثم اعرضها بالشكل الذي يحدّده `docs/design-system.md`،
     ملفوفة بـ `StateBoundary` لتغطية الحالات الخمس
   - **صفحة النموذج** بـ React Hook Form + Zod، رسائل من الترجمة، `applyServerErrors` لأخطاء الخادم، و `disabled` أثناء الحفظ
   - **صفحة التفاصيل** إن كان القسم يستحقها
4. `index.ts` يصدّر الواجهة العامة للموديول
5. **تسجيل الشاشات: صف في `src/app/routes.tsx`** لكل شاشة، فيه `path` و `component` (بـ `lazy()`) و `labelKey` و `permission`. التنقّل يظهر تلقائيًا — لا تبنِ قائمة ولا رابطًا يدويًا.
6. كل النصوص في `src/locales/ar.json` و `en.json` بمفاتيح `<feature>.<screen>.<key>`
7. تأكيد قبل الحذف، و Toast بعد كل عملية
8. Vitest لكل مكوّن فيه منطق — يختبر **السلوك لا الشكل**
9. البوابة: `npm run check`

> **التنسيق:** التزم بـ `theme.css` و `docs/design-system.md`. إن لم يكن `/صمم` قد
> شُغِّل بعد، ابنِ الشاشات بلا تنسيق واذكر لصاحب النظام أن شكلها يأتي مع `/صمم`.
> **لا تخترع ألوانًا ولا تخطيطًا من عندك.**

## المرحلة 4 — التحقق الذاتي

قبل أن تعلن الانتهاء، شغّل بنفسك:
```bash
cd frontend && npm run check
cd backend && ./vendor/bin/pint && ./vendor/bin/phpstan analyse && php artisan test
```
إن فشل أي منها، أصلحه ثم أعد التشغيل. لا تسلّم عملًا لا يمر بهذه الفحوصات.

## المرحلة 5 — التسليم

سجّل نقطة حفظ باسم مفهوم حتى يستطيع `/تراجع` عرضها لاحقًا بلغة يفهمها:
```bash
git add -A && git commit -q -m "أضفنا قسم <الاسم بالعربية>"
git tag -a "milestone/$(date +%Y%m%d-%H%M)" -m "أضفنا قسم <الاسم بالعربية>"
```

ثم اكتب له ملخصًا **بلغة بسيطة**، وليس قائمة ملفات:

> "خلص قسم «الفواتير» ✅
>
> صار عندك:
> · شاشة تعرض كل الفواتير مع بحث وفرز وتقسيم صفحات
> · شاشة لإضافة فاتورة وتعديلها
> · حماية: المحاسب ما يقدر يحذف
> · وكل عملية تنحفظ في سجل: مين سواها ومتى
>
> اكتب `/جرب` عشان تشوفه بعينك."

⚠️ لا تقل "تم بنجاح" قبل أن يجرّبه هو بنفسه.
