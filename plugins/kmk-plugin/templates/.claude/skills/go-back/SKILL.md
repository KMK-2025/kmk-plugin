# التراجع إلى نقطة سابقة

## نقاط الحفظ المتوفرة
```!
git log --oneline -15 --date=format:'%m-%d %H:%M' --pretty=format:'%h · %ad · %s'
git status --short
```

---

## الخطوة 1 — اعرض عليه الخيارات بلغته

حوّل قائمة نقاط الحفظ إلى عرض مفهوم، **بدون أرقام Git**:

> "هذه آخر نقاط الحفظ. على وين تحب نرجع؟
>
> 1️⃣ قبل ساعة — بعد ما أضفنا شاشة الفواتير
> 2️⃣ اليوم الصبح — بعد ما عدّلنا الألوان
> 3️⃣ أمس المساء — بعد ما خلّصنا قسم العملاء
>
> اكتب الرقم."

---

## الخطوة 2 — احمِ عمله الحالي أولًا

قبل أي تراجع، احفظ الوضع الحالي في فرع جانبي حتى لا يضيع شيء نهائيًا:

```bash
git branch "نسخة-احتياطية-$(date +%Y%m%d-%H%M)"
```

أخبره:
> "حفظت نسخة من الوضع الحالي في مكان آمن، فلو ندمت نقدر نرجعها."

---

## الخطوة 3 — حذّره من البيانات

⚠️ التراجع يرجّع **الكود** فقط. البيانات التي أدخلها في قاعدة البيانات **لا ترجع ولا تُحذف**.

إن كان التراجع يعبر Migration (أي أن بنية قاعدة البيانات تغيّرت بينهما)، **قف واشرح**:
> "انتبه: بين هذه النقطة والوضع الحالي غيّرنا شكل قاعدة البيانات. الرجوع للكود القديم ممكن يخلي النظام ما يشتغل صح مع البيانات الحالية. تحب:
> أ) نرجع الكود وقاعدة البيانات معًا (بنعمل نسخة احتياطية أول)
> ب) نصلح المشكلة الحالية بدل ما نرجع"

---

## الخطوة 4 — نفّذ

```bash
git checkout <النقطة المختارة> -- .
```
أو `git revert` إن كان الأنسب. **لا تستخدم `git reset --hard` أبدًا** — لا رجعة منه.

---

## الخطوة 5 — تأكّد

شغّل الفحوصات، ثم قل:
> "رجعنا للنقطة اللي اخترتها ✅
> اكتب `/test` وتأكد إنو كل شي رجع زي ما كان."
