# التراجع إلى نقطة سابقة

## المحطات المسمّاة
```!
git for-each-ref --sort=-creatordate --count=10 --format='%(refname:short) · %(creatordate:relative) · %(contents:subject)' refs/tags/milestone 2>/dev/null || echo "لا توجد محطات مسمّاة بعد"
```

## آخر نقاط الحفظ التلقائية
```!
git log --oneline -10 --pretty=format:'%h · %ad · %s' --date=format:'%m-%d %H:%M'
git status --short
```

---

## الخطوة 1 — اعرض عليه الخيارات بلغته

اعتمد على **المحطات المسمّاة** أولًا — هي مفهومة لأنها تحمل وصفًا عربيًا.
النقاط التلقائية لا تُعرض إلا إن طلب تفصيلًا أدق أو لم توجد محطات.

حوّل القائمة إلى عرض مفهوم، **بدون أرقام Git**:

> "هذه آخر نقاط الحفظ. على وين تحب نرجع؟
>
> 1️⃣ قبل ساعة — بعد ما أضفنا شاشة الفواتير
> 2️⃣ اليوم الصبح — بعد ما عدّلنا الألوان
> 3️⃣ أمس المساء — بعد ما خلّصنا قسم العملاء
>
> اكتب الرقم."

---

## الخطوة 2 — احمِ عمله الحالي أولًا

قبل أي تراجع، احفظ الوضع الحالي في فرع جانبي حتى لا يضيع شيء نهائيًا:

```bash
git branch "backup/$(date +%Y%m%d-%H%M)"
```

أخبره:
> "حفظت نسخة من الوضع الحالي في مكان آمن، فلو ندمت نقدر نرجعها."

---

## الخطوة 3 — حذّره من البيانات

⚠️ التراجع يرجّع **الكود** فقط. البيانات التي أدخلها في قاعدة البيانات **لا ترجع ولا تُحذف**.

إن كان التراجع يعبر Migration (أي أن بنية قاعدة البيانات تغيّرت بينهما)، **قف واشرح**:
> "انتبه: بين هذه النقطة والوضع الحالي غيّرنا شكل قاعدة البيانات. الرجوع للكود القديم ممكن يخلي النظام ما يشتغل صح مع البيانات الحالية. تحب:
> أ) نرجع الكود وقاعدة البيانات معًا (بنعمل نسخة احتياطية أول)
> ب) نصلح المشكلة الحالية بدل ما نرجع"

---

## الخطوة 4 — نفّذ

استبدل `<النقطة>` باسم المحطة أو رقمها، و`<الوصف>` بالوصف العربي الذي عرضته عليه:

```bash
# ١. اجعل الملفات مطابقة تمامًا للنقطة المختارة.
#    git rm يحذف المتتبَّع فقط — .env و node_modules و vendor بأمان لأنها غير متتبَّعة.
git rm -r --force --quiet .
git checkout <النقطة> -- .

# ٢. سجّلها كخطوة جديدة للأمام
git add -A
git commit -q -m "رجوع إلى: <الوصف>"
```

**لماذا هكذا ولماذا لا `git checkout <النقطة> -- .` وحدها:** تلك تُرجع الملفات القديمة
لكنها **لا تحذف الملفات التي أُضيفت بعد تلك النقطة**، فيبقى نصف القسم الذي أردنا
إلغاءه ويصير النظام خليطًا معطوبًا. الحذف أولًا ثم الاستعادة يضمن مطابقة تامة.

**وممنوع نهائيًا `git reset --hard`** — يمحو التاريخ بلا رجعة. ما نفعله هنا خطوة
**إلى الأمام**، فيستطيع التراجع عن تراجعه لاحقًا إن ندم.

---

## الخطوة 5 — تأكّد

أعد تثبيت الاعتماديات إن تغيّرت ملفاتها، ثم شغّل الفحوصات:
```bash
cd frontend && npm ci && npm run check
cd backend && composer install && php artisan migrate --force && php artisan test
```

ثم قل:
> "رجعنا للنقطة اللي اخترتها ✅
> اكتب `/جرب` وتأكد إنو كل شي رجع زي ما كان."
